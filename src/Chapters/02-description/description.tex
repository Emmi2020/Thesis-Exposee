\section{Problem Description}

\subsection*{Current Situation}

When creating D-FMEAs for new components, engineers typically rely on copy-paste workflows using only one or a few reference documents instead of systematically analyzing the full historical knowledge pool. Existing D-FMEAs for similar components (H1B\footnote{Bent-axis axial piston motor product family in Hydrostatic product family at Danfoss Power Solutions.} and H1P\footnote{Closed-circuit axial piston pump product families in Hydrostatic product family at Danfoss Power Solutions.}) are stored as centralized Excel files in a SharePoint Library, containing valuable insights about failure modes, severity assessments, and mitigation actions. This underutilization of available knowledge results in inefficient processes and risks overlooking critical design issues.

\subsection*{Problem}

Manually searching and propagating these Excel files leads to immense time consumption and cognitive load. consequently, critical failure risks are frequently overlooked because engineers only refer to a single baseline document rather than investigating the entire knowledge pool. From an IT perspective, there is a lack of an automated ingestion pipeline capable of resolving complex table layouts, structing the data and serving it securely to Users.
